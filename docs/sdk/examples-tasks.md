# Task Management Examples

The SDK task methods are acknowledged operations. Creation returns the persisted
server task ID. Completion, failure, and cancellation resolve only after MXF applies
the legal transition to the exact task in the exact channel; an authorization,
state, dependency, or persistence failure rejects.

## Prerequisites

See [Basic Examples](examples-basic.md#prerequisites) for authentication and agent
creation.

## Create and assign a task

```typescript
import { Events, MxfSDK } from '@mxf-dev/sdk';
import type { TaskConfig } from '@mxf-dev/sdk';

const config: TaskConfig = {
    title: 'Analyze Data',
    description: 'Analyze customer feedback from Q4',
    assignedAgentIds: ['analyst-agent'],
    assignmentScope: 'single',
    assignmentStrategy: 'manual',
    priority: 'high',
    metadata: {
        deadline: '2026-12-31'
    }
};

const taskId = await coordinator.mxfService.createTask(config);
console.log('Persisted task ID:', taskId);
```

The `taskId` is generated by the server's persistence layer. A client correlation ID
is never presented as the task's identity. For manual assignment, MXF persists the
task as `assigned` and emits one `Events.Task.ASSIGNED` delivery to each actual
assignee.

## Complete assigned work

```typescript
worker.on(Events.Task.ASSIGNED, async (payload) => {
    if (payload.data.toAgentId !== worker.agentId) {
        return;
    }

    const taskId = payload.data.taskId;

    try {
        const report = await analyzeFeedback(payload.data.task);

        await worker.mxfService.completeTask(taskId, {
            reportId: report.id,
            findings: report.findings
        });
    } catch (error) {
        const reason = error instanceof Error ? error.message : String(error);
        await worker.mxfService.failTask(taskId, reason);
    }
});
```

Completing and failing are both terminal outcomes and are gated the same way:
when the task names a `completionAgentId`, only that agent may report either
outcome; otherwise any assigned participant may. MXF compares the authenticated
agent identity, channel, assignee list, completion designation, dependency
state, and legal source status in the same authoritative transition. A
`failTask()` call from a contributor to a task another agent is designated to
finish is refused.

The SDK's automatic failure reports follow the same rule. When a contributor's
task handler throws, or the agent reaches its iteration limit without calling
`task_complete`, the SDK reports the failure only if this agent holds completion
authority; a contributor surfaces the error on `Events.Agent.ERROR` (phase
`task_execution` or `max_iterations`) and leaves the task open.

## Cancel assigned work

```typescript
await worker.mxfService.cancelTask(taskId, 'The upstream dataset was withdrawn');
```

Agent credentials may cancel work assigned to that agent while it is `assigned` or
`in_progress`. Channel owners and administrators use the authenticated REST task
transition endpoint for owner-level lifecycle actions, including cancellation of a
pending task. A generic task patch cannot change `status` or terminal result fields.

## Multiple assignees

```typescript
const taskId = await coordinator.mxfService.createTask({
    title: 'Prepare release evidence',
    description: 'Run independent security, lifecycle, and package checks',
    assignedAgentIds: ['security-agent', 'lifecycle-agent', 'package-agent'],
    assignmentScope: 'multiple',
    assignmentStrategy: 'manual',
    coordinationMode: 'collaborative',
    completionAgentId: 'package-agent',
    priority: 'high'
});
```

Assignment delivery is recipient-specific. Two agents sharing a process-local SDK
event bus cannot consume one another's assignment merely because they are in the
same channel.

## Observe lifecycle events

```typescript
import { Events, getTaskCompletionOutput } from '@mxf-dev/sdk';

const onCompleted = (payload: any): void => {
    const summary = getTaskCompletionOutput(payload.data.task)?.summary;
    console.log('Task completed:', summary);
};

worker.on(Events.Task.COMPLETED, onCompleted);
worker.on(Events.Task.FAILED, payload => {
    console.error('Task failed:', payload.data.error);
});
worker.onTaskCancelled(taskData => {
    console.log('Task cancelled:', taskData.taskId);
});

// Remove exactly the handler registered above.
worker.off(Events.Task.COMPLETED, onCompleted);
```

For ordinary agent code, prefer `agent.on()`: it applies the public-event whitelist
and recipient checks. `agent.mxfService.on()` is available when a channel-filtered
view is specifically needed.

`result.output` on the completed task holds different things depending on which
path completed it. When an agent finishes the work by calling `task_complete`,
MXF writes a `TaskCompletionOutput` there (`agentId`, `summary`, `reportedSuccess`,
`requestId`, and optional `details`/`nextSteps`). When a caller completes the task
directly through `completeTask()` or the REST completion route, `output` is
whatever value that caller passed — there is no guaranteed shape. Neither path
ever populates a `result.summary` field, so read the summary through
`getTaskCompletionOutput(payload.data.task)?.summary` rather than assuming
`result.summary` exists.

## Handle lifecycle rejection

```typescript
try {
    await worker.mxfService.completeTask(taskId, { artifact: 'report.json' });
} catch (error) {
    console.error('Task was not completed:', error);
}
```

A rejected call means the server did not confirm the requested transition. Common
causes include a sibling agent attempting the transition, a channel mismatch, unmet
dependencies, a terminal task, or a disconnected exact agent socket. The SDK does
not manufacture a successful completion after a timeout.
